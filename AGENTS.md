# Batas kerja aplikasi doorprize baru

- Seluruh perubahan untuk aplikasi baru hanya boleh dilakukan di direktori `doorprize-baru/` dan turunannya.
- Jangan mengubah aplikasi lama atau berkas di luar direktori ini, termasuk konfigurasi, dependensi, lockfile, database, dan pengaturan deployment aplikasi lama.
- Tempatkan kode, konfigurasi, dependensi, dokumentasi, dan hasil build aplikasi baru di direktori ini. Jangan menggunakan konfigurasi atau kredensial aplikasi lama secara otomatis.
- Pengembangan dilakukan secara lokal terlebih dahulu.
- Baca `BRIEF.md` sebagai acuan kebutuhan dan keputusan pengguna yang telah disepakati.
- Jangan mengarang keputusan jika kebutuhan membingungkan atau saling bertentangan. Tanyakan kepada pengguna secara ringkas.
- Gunakan bahasa Indonesia yang konsisten pada antarmuka. Jaga penamaan dan relasi backend agar jelas, konsisten dengan frontend, dan mudah dibaca.
- Utamakan struktur modular, kecepatan, keteraturan UI, dan konsistensi di seluruh aplikasi.
- Kerapian dan keterstrukturan backend hingga frontend adalah batasan utama pengguna, bukan pekerjaan kosmetik di akhir. Sebelum menambah fitur, tentukan modul pemilik, alur data, dan bagian UI yang diperbarui. Rapikan bagian yang terdampak sebelum melanjutkan jika tanggung jawabnya mulai bercampur.
- Backend: controller/API mengoordinasikan request/respons, service menjalankan aturan bisnis dan transaksi, repository memuat query SQL, view hanya menyajikan tampilan. Pertahankan core yang tipis; jangan menambah abstraksi/lapisan tanpa kebutuhan nyata.
- Frontend: pisahkan navigasi, akses API, interaksi fitur, formulir/komponen bersama, dan presentasi sesuai tanggung jawab. Jangan menumpuk fitur baru ke `operator.js` atau `management-controller.js`; modul undian, import, dan laporan harus memiliki modulnya sendiri. Pecah pengelolaan peserta/hadiah/isian ketika penambahan perilaku membuat pengendalinya sulit dibaca.
- Nama field, status, payload API, dan pesan validasi harus konsisten antara database, backend, dan frontend. Gunakan ulang komponen, token CSS, ukuran kontrol, serta ikon bersama; hindari salinan logika dan styling yang menyimpang per fitur.
- Hindari pembacaan ulang seluruh data pada setiap aksi aplikasi. Ambil hanya kolom dan baris yang diperlukan; perbarui hanya bagian yang berubah.
- Animasi pengacakan tidak boleh memicu query atau pembacaan daftar peserta berulang. Validasi kelayakan peserta dan stok tetap dilakukan saat transaksi terkait.
- Mesin undian nyata tersedia pada DrawService/DrawRepository, RandomSelection dan PrizeAllocation. DrawController/RoundPrizes mengelola operator, DrawState membawa perubahan lintas jendela, DrawPresentation/result-layout mengelola hasil. Seed animasi bukan pemilihan pemenang. Coba animasi telah dihapus atas permintaan pengguna; animasi hanya mengikuti putaran nyata.
- Koreksi animasi sudah diterapkan: satu baris glyph terus acak sampai Stop, tanpa siklus membentuk nama. shuffle-model tidak menerima target nama; tempo flip tiap glyph bervariasi. Start tidak membaca sampel nama peserta untuk visual. Node didaur ulang, animasi hanya aktif saat terlihat, dan hasil nyata tampil setelah Stop.
- participant_pool memakai slot rapat dan primary key (event_id, position). Trigger migrasi 003 memperbarui hanya peserta yang kelayakannya berubah; penghapusan menukar slot terakhir. Jangan membangun ulang pool atau membaca seluruh nama saat Mulai/Stop. Lock acara mendahului mutasi; status/stok, pool, versi dan audit harus atomik.
- Saat mengembangkan, baca hanya berkas atau potongan yang relevan; gunakan konteks yang sudah dibaca dan jangan mengulang pemindaian seluruh proyek tanpa alasan.
- Pondasi saat ini: PHP 8.3 modular tanpa dependensi framework runtime, PostgreSQL, Tailwind yang dibuild lokal. Lihat `README.md` dan `docs/ARCHITECTURE.md` sebelum melanjutkan modul terkait.
- Operator/output, CRUD peserta/hadiah/isian, Persiapan, undian utuh, filter, edit massal dan riwayat aktivitas tersedia dengan penyimpanan lokal. Runtime portabel memakai PGlite persisten melalui jembatan internal, PHP native memakai PDO PostgreSQL jika dikonfigurasi. Import Excel/template/pratinjau dan aturan duplikasi tersedia. Google Sheets melalui konektor sekali pasang tersedia. Daftar pemenang historis dan PDF tersedia. Auth email/password, sesi 30 hari, logout/CSRF dan isolasi pemilik tersedia; preview cloud PHP/PDO/pooler/Storage dan isolasi pemilik telah diuji; status terbaru ada di docs/DEPLOYMENT.md.
- ParticipantController mengelola tabel/paginasi/pilihan/edit massal; ManagementController mempertahankan editor satu record bersama dan isian. FilterControl digunakan ulang oleh daftar peserta dan DrawFilters. Query/opsi mengambil maksimal 50 nilai/baris per halaman; Pilih semua memakai komplemen/predikat, bukan mengunduh semua ID/nama.
- Menu Peserta mempunyai satu Filter peserta: Status menjadi kelompok pertama, lalu Nama/isian. Status memakai komponen switch/multi-centang/Pilih semua yang sama, dengan opsi enum lokal. ParticipantController memisahkan status_filter dari predikat isian saat mengirim query; status aktif tanpa pilihan menghasilkan nol hasil. Jangan mengembalikan dropdown status terpisah.
- ParticipantFilter/ParticipantQuery menormalkan filter dan klausa aman; ParticipantQueryRepository dan ParticipantBulkRepository memuat SQL. BulkService memvalidasi skema, versi pilihan dan status yang dilindungi dalam transaksi. draw_filter_pool dicache sampai kriteria berubah, lalu dirawat trigger hanya untuk peserta yang berubah. participants_version bertambah per statement, bukan per baris. Nama/isian: OR dalam satu kelompok dan AND antarkelompok; nilai kosong = string kosong. Jangan menambah polling atau membangun ulang pool pada setiap putaran.
- SettingsController mengelola formulir Persiapan; PresentationView merender SVG; PresentationState membawa konfigurasi kecil lintas jendela tanpa polling. PrizeController/PrizeStore menangani list/urutan hadiah. ManagementController mempertahankan editor bersama dan pengelolaan peserta/isian. Jangan menumpuk kembali perilaku tersebut pada satu file.
- Pengaturan visual memakai settings_version tersendiri. Perubahan peserta/hadiah tidak boleh membuat formulir visual bentrok tanpa alasan. Background hadiah disimpan pada prizes.background_path dengan versi record masing-masing. Upload raster hanya melalui BackgroundAsset; jangan kirim isi gambar atau daftar peserta lewat kanal konfigurasi.
- Aksi edit/hapus peserta, hadiah, dan isian tambahan memakai pensil/× yang sama. Kontrol Mulai, Sahkan, Eliminasi, dan Kosongkan memakai ikon+teks dan tinggi yang sama. Grup tombol dan jumlah nama terpusat pada preview; tombol maksimal 412px isi: Mulai selebar gabungan tiga tombol di bawahnya; tiga tombol bawah sama lebar, tanpa wrap.
- Output pada Chrome desktop mendukung fullscreen langsung dari operator: fullscreen visual dahulu, lalu jendela operator terpisah. Gunakan `PresentationSession` dan delegasi fullscreen untuk penggunaan ulang; jangan mengembalikan alur popup-output dahulu yang memerlukan klik tambahan pada output.

- Imports: ImportService mengoordinasikan validasi/transaksi; ImportRepository menangani batch/chunk/commit; ImportPreviewRepository menilai kelompok lewat window SQL; ImportRows memvalidasi ulang baris di server. Jangan menulis ke participants sebelum commit. Jaga idempotensi, versi peserta/aturan/skema dan audit tunggal, termasuk ketika respons commit hilang.
- Excel dibaca/ditulis ExcelClient + excel-worker, bundle lokal ExcelJS dimuat saat diperlukan. Template ada di excel-template, pemetaan di ImportMapping, pratinjau di ImportPreview, kontrol di ImportController. Jaga token sesi saat dialog dibatalkan/dibuka ulang. Tidak ada polling/unduh ulang seluruh peserta.
- DuplicatePolicy/DuplicateRepository adalah aturan peserta, dipakai ulang CRUD, massal dan import. Semua kunci terpilih harus terisi; trim + case-insensitive tepat, tanpa fuzzy/simbol substitusi. Winner/tereliminasi tetap jangkar. Rekonsiliasi hanya kelompok lama/baru pada edit; rebuild penuh hanya saat aturan berubah/penghapusan isian memengaruhi kualitas.

- Google Sheets berada di Modules/Imports/Google. GoogleSourceService mengelola koneksi/pemetaan/jadwal/resolve, GoogleSyncService memisahkan reserve lease → HTTP di luar transaksi → validasi ulang/apply, GoogleRowPlan menjalankan merge 3 arah. Repository memuat seluruh SQL. Jangan membawa secret ke list, audit atau BroadcastChannel.
- GoogleRowService menangani maksimal 200 perubahan per request dan hanya kelompok duplikasi terdampak. Delta kosong tidak menyentuh participants/pool. Source row UUID stabil dan hash mencegah insert ulang. Initial snapshot menahan Mulai sampai selesai; pending draw menahan apply. Deadline server diperiksa sebelum/sesudah HTTP.
- Keputusan pengguna: baris dihapus → Tereliminasi, winner tetap. Isian operator dipertahankan bila isian yang sama berubah di sumber; simpan incoming/conflict, jangan menimpa diam-diam. Perubahan pada isian lain digabung tanpa menghapus edit lokal. Status winner/eliminated tidak diaktifkan ulang oleh sumber.
- GoogleSync hanya aktif di operator, menggunakan metadata kecil, Web Locks/BroadcastChannel dan lease DB. is-output-host/output renderer tidak mengambil sumber. Scope setiap response mencakup event/source dan revision; respons sesi dialog lama harus diabaikan.
- resources/google-sheets/connector.gs adalah konektor siap salin, bukan skrip yang dijalankan lokal terhadap Google pengguna. Ia menambah ID/log tersembunyi, mengambil snapshot sekali, merekam edit/form submit, antrean pointer pemulihan dan tail baris baru. Scan identitas/resnapshot hanya pada perubahan struktur. Google API/script lain perlu memanggil catatPerubahanDoorprize; jangan mengklaim semua perubahan eksternal otomatis memicu trigger Google.
- Target hosting disepakati Vercel Container PHP + Supabase PostgreSQL. State sinkronisasi tidak boleh memakai file/memori proses produksi. HTTP job Map hanya adapter dev WASM untuk menjaga antrean kontrol. Supabase migrations berisi baseline 001–005 lalu migrasi Google, dibuat CLI; check:supabase-schema menguji paket pada DB kosong dan RLS. CloudRuntime menolak konfigurasi cloud yang belum lengkap. Storage privat dan HTTPS/pooler/Container telah diuji pada preview nyata; jangan mengembalikan penyimpanan file lokal ke produksi. Jangan menganggap file Docker berarti sudah deploy/siap publik.

- CanvasGeometry (PHP) memiliki default dan validasi batas. canvas-geometry.js memuat fit/validasi dan resolusi anchor; CanvasControls mengelola slider tengah/form/max dinamis serta baseline satu sesi pengetikan, CanvasPreview menyesuaikan frame tanpa query/resize polling. Hindari mengembalikan scaleArea lama yang bergantung pada packet preview yang sudah berubah.
- Kontrak visual: area_x/area_y adalah jarak dari area_anchor_x (left/right) dan area_anchor_y (top/bottom). Default lama tetap left/top. resolveNameArea dipanggil satu kali pada batas PresentationView sebelum standby, guide, ShuffleAnimation dan DrawPresentation; modul layout/animasi menerima koordinat absolut, jangan meresolusikannya dua kali.
- background_fit cover/contain berlaku untuk background utama maupun hadiah. Preview memakai rasio canvas, tinggi dibatasi CSS; is-output-host tetap memakai viewport fullscreen. Default canvas berasal dari CanvasGeometry::DEFAULTS yang dikirim sebagai metadata view, bukan konstanta JS ganda; reset hanya draft geometry dan perlu Simpan.

- Editor canvas hanya menampilkan area_offset_x/area_offset_y (slider signed, 0 di tengah). centeredGeometry membaca acuan lama menjadi absolute left/top tanpa loncatan; CanvasControls.read mengirim area_x/area_y left/top ke API yang kompatibel. Posisi mengizinkan kelipatan 0,5 pixel; ukuran tetap integer. editGeometry mereset ukuran/posisi sumbu ketika dimensi canvas berubah; ukuran area berubah dari pusat lalu dibatasi.
- FieldVisibilityControls memiliki switch visual pada list isian dan draft show_field_1/2/3 di visual_settings (default true). ManagementController menyiarkan field-list-rendered, tanpa mengambil tanggung jawab draft visual. SettingsController menyimpan/memuat konfigurasi; result-layout menjaga rasio 100/50/25/25 berdasarkan slot dan merapatkan isian tersembunyi. Jangan memakai switch ini sebagai kunci filter/duplikasi.
- seed:sample hanya untuk HTTP loopback lokal, mengikuti metadata isian/aturan dan pipeline import yang sama. Manifest batch/seed ada di .cache/sample-participants/<port>; pengulangan commit idempoten. Jangan menimpa data lama, membuat label tambahan atau mengaktifkan aturan duplikasi otomatis.

- output-typography.js memiliki shuffleTypography bersama untuk ukuran glyph dan acuan Nama; metrik advance dicache per context/font. resultSizeLimit menurunkan batas acuan menurut jumlah pemenang (reference / count^0,25). result-layout memilih grid satu baris per nama; ukuran umum memakai lebar terbesar dari blok yang tidak melampaui median lebar × 1,6, lalu hanya blok yang lebih lebar diperkecil. Rasio isian selalu mengikuti ukuran blok masing-masing. Jangan mengembalikan wrapping, ellipsis, slider wajib, atau menjadikan satu nama ekstrem patokan semua pemenang. Standby satu baris bold 700 memakai 68% acuan glyph dan dibatasi area/font aktual.
- DrawPresentation memakai ulang node hasil per participant_id. ResultEntrance menjalankan opacity/translate 380 ms dengan stagger maksimal 160 ms hanya saat hasil putaran baru tiba; edit visual/pengesahan tidak memulai ulang. Hasil yang dimuat ulang langsung stabil. Reduced motion memakai fade 120 ms; clear/pagehide membatalkan animasi, halaman tersembunyi menyelesaikannya. Jangan menambah polling/frame JS untuk transisi hasil.

- Riwayat memiliki tab Pemenang (default) dan Aktivitas; masing-masing dimuat hanya saat terlihat. WinnerRepository/Service memuat hanya draws confirmed + draw_entries snapshot. Cursor tuple draw_id/position memakai draw_entries_event_idx, list 50 dan export 500 per halaman. snapshot adalah ID putaran confirmed maksimum milik acara; satu pending per acara dan confirmed immutable menjaga batas ini stabil saat pengesahan baru. Metadata/total dibaca hanya pada permintaan awal.
- WinnerController hanya menginvalidasi saat pengesahan baru; edit peserta/hadiah/isian tidak mengubah laporan historis. ReportClient membuat worker hanya saat export dan membatalkannya saat ditutup; jangan memuat PDF/font di startup atau membawa kerja PDF ke main thread. winner-report-worker mengambil halaman winners untuk snapshot yang sama; winner-report membentuk A4 landscape font ≥12, header/footer berulang dan tabel terpisah jika label isian historis berubah. Isian tersembunyi pada visual tetap masuk laporan.

- FilterDropdown dipakai bersama Undian/Peserta: details ringkas, popup fixed maksimal 380 px dalam viewport, tutup dengan klik luar/Escape/pindah menu. FilterControl menyiarkan statechange saat load/restore/notify/lock; dropdown tidak menjalankan query. Tombol biru + jumlah kelompok dan ikon × hanya untuk predikat efektif (include, termasuk pilihan kosong, atau exclude dengan pengecualian); exclude kosong/Pilih semua tidak ditandai membatasi.
- FilterControl.clear mengosongkan seluruh kelompok/nilai/search opsi, membatalkan debounce dan menaikkan generation agar respons opsi lama diabaikan; callback query/count dipanggil sekali. Hapus filter undian terkunci saat pending. Draft untuk putaran berikutnya tidak ditimpa aksi Kosongkan layar; konfigurasi tetap dipersistenkan saat Mulai. Reset filter Peserta mempertahankan searchbar, serta mereset paginasi/pilihan massal melalui queryChanged.

- Target yang ditentukan pengguna: GitHub `pranaa123/luckydraw_liberteam`; Vercel Kapsul Photobooth (slug terverifikasi `kapsul-photobooth`), proyek `luckydraw-liberteam`, domain `luckydraw-liberteam.vercel.app`; Supabase project ref `mjqkrtrjrctdqnbzbbwb`. Jangan menghubungkan proyek lain atau mengambil kredensial aplikasi lama. Detail non-rahasia ada di BRIEF.md; password tidak boleh dicatat di berkas.
- AuthService/AuthRepository/AuthSession menangani akun pemilik dan cookie HttpOnly SameSite=Lax 30 hari; hanya hash password/token dalam database privat doorprize_auth. Tidak ada pendaftaran umum atau password bawaan dalam source. EventContext menerima user dari sesi terverifikasi; audit memakai ownerId, bukan konstanta lokal.
- Database dengan ownerId selalu memakai role doorprize_app dan claim SET LOCAL per transaksi; jangan menggantinya dengan sesi koneksi global atau membungkus seluruh request Google dalam transaksi. Snapshot read-only ditetapkan saat BEGIN sebelum claim. Public API memerlukan scope sesi dan POST memerlukan CSRF/origin yang sama. Background melewati front controller dan registry milik acara, termasuk saat memakai dev server/native/Caddy.
- auth-context memberi namespace sesi pada BroadcastChannel, Web Locks dan nama jendela. AuthController menutup visual lintas jendela saat logout/401/kedaluwarsa; pemeriksaan ulang hanya saat halaman kembali terlihat/BFCache, tanpa polling. PDF worker membawa header scope; jangan mengirim cookie/token login ke worker atau broadcast. Akun QA hanya di scripts/auth-fixture.mjs dan database QA terpisah.

- DrawStatus merender status Siap/Sedang mengundi/Menunggu keputusan/Disahkan langsung dari DrawState. Status biru saat rolling, kuning saat pending result; lock notice menerangkan mengapa jumlah/hadiah/filter terkunci. Setelah refresh tetap mengikuti DB tanpa request tambahan. Kosongkan hanya menyelesaikan pending sebagai cleared atau membersihkan tampilan confirmed, tanpa mengubah peserta/stok/pengesahan sebelumnya.

- Layout operator terbaru: panel kontrol boleh lebih lebar dari tombol. Output di kiri/filter undian di kanan toolbar yang sama; jumlah nama berada di kanan seluruh grup tombol, turun ke bawah kanan bila ruang sempit. Container query hanya pada pembungkus tombol/jumlah, bukan ancestor popup fixed filter. Nama client/acara berdampingan dalam formulir Persiapan (bukan visual output). Penanda Pengembangan lokal dihapus.

Periksa staged files/kredensial sebelum commit/push. Seluruh storage/.env/cache/upload/kunci diabaikan. Identitas login bukan dokumentasi publik; alamat commit memakai GitHub noreply. Pertahankan assertion performa <1000ms di check-draws/check-filters; jangan meniadakan threshold demi meloloskan pemeriksaan.
